## 3. `TDimTP` 两点标注

### 网络线索

无网络线索。未找到 `TDimTP` 或“两点标注”的命令行提示原文。

### 置信度

低。该命令名可与“两点标注”对应，但本轮网络调研无法判断它是否需要先选墙、先给尺寸线位置，或是否依赖已有天正构件。

### 建议的最小试驱动方案

不建议继续用“任意两点”盲试。应先捕获提示词，尤其确认输入顺序是否类似已验证的 `TDimMP`，或者是否必须选择可标注对象。

建议后续真机捕获序列：

```text
TDimTP -> 观察首个提示
```

根据首个提示分支：

- 若提示选择对象：先创建一段 `TCH_WALL`，再选择墙体，随后按提示给标注位置或两点。
- 若提示指定点：记录点 1、点 2、尺寸线位置的准确顺序。
- 若弹参数对话框：标为不适合静默命令行封装，除非找到无对话框开关。

建议的候选试驱动只作为提示捕获后的验证：

```text
TDimTP -> 标注位置点 -> 起点 -> 终点 -> 回车
TDimTP -> 起点 -> 终点 -> 标注位置点 -> 回车
```

## 4. `TSWall` 单线变墙

### 网络线索

无网络线索。未找到“选择 LINE 后如何指定墙宽/左右宽/高度”的可靠公开说明。

### 置信度

低。中文命令名表明它可能把普通单线转换为天正墙，但本轮网络资料未说明它的交互顺序，也未说明是否必须使用面板当前墙参数。

### 建议的最小试驱动方案

不建议假定宽度可以通过命令行输入。后续真机捕获应先创建一条原生 `LINE`，再启动命令并观察提示。

建议捕获项：

- 首个提示是否为“选择对象”。
- 选择 `LINE` 后是否直接转换，还是继续询问墙宽、左宽、右宽、对齐方式。
- 是否弹墙体参数面板或依赖当前墙体参数。
- 转换后是否生成 `TCH_WALL`，以及原 `LINE` 是否被删除。

候选试驱动：

```text
LINE -> 两点建线
TSWall -> 选择 LINE -> 回车
```

若提示要求宽度，再记录提示原文后尝试：

```text
TSWall -> 选择 LINE -> 回车 -> 240 -> 回车
```

但在没有提示原文前，不建议把 `240` 作为固定序列写入模板。

### 网络线索

无网络线索。未找到“搜索房间”的命令行提示序列，也未找到是否生成 `TCH_SPACE` 的公开说明。

### 置信度

低。无法从公开资料确认它是自动全图搜索、框选搜索，还是需要先选择封闭边界。

### 建议的最小试驱动方案

后续真机测试前应构造明确的封闭条件：

- 四段闭合墙体，优先用 `TCH_WALL`。
- 备选：四段原生 `LINE` 闭合矩形，用于判断是否支持普通线边界。
- 命令前后统计实体数，并检查新增实体类型是否为 `TCH_SPACE` 或其他房间对象。

建议先捕获提示：

```text
TUpdSpace -> 观察首个提示
```

根据提示再分支测试：

```text
TUpdSpace -> 回车
TUpdSpace -> 框选闭合区域 -> 回车
TUpdSpace -> 点取闭合区域内部点 -> 回车
```

成功判据：

- 新增房间对象实体。
- 读取实体 DXF 组码或 ActiveX 对象名，确认是否为 `TCH_SPACE`。
- 命令结束后 `CMDACTIVE=0`，不能残留等待输入状态。

- 门/窗模式是否存储在系统变量、注册表或配置文件中。
- `TCH_OPENING` 窗台高的真实 COM/ActiveX 属性名。

### 置信度

低到中。项目既有真机经验可以说明当前面板模式会影响插入对象类型，但本轮网络调研未找到外部来源确认模式切换机制或窗台高属性名。

### 建议的最小试驱动方案

不建议通过猜测属性名强行写窗台高。后续应优先解决“如何切到窗模式”，再做属性枚举。

建议下一步顺序：

1. 手动把天正门窗面板切到“窗”模式。
2. 使用 `TOpening -> 墙上点 -> 回车` 插入对象。
3. 枚举 `TCH_OPENING` 可读属性，并记录门模式与窗模式差异。
4. 对候选窗台高属性做 `vlax-put-property` 后回读与图形检查。

建议候选属性仍可保留为探测名单，但不能作为已确认事实：

```text
DoorSill
SillHeight
WindowSill
WindowSillHeight
Bottom
Elevation
```

模式切换方向建议：

- 先查天正门窗面板是否有可见控件状态或配置文件变化。
- 再查注册表或 `%APPDATA%` / 天正安装目录下配置文件是否在切换门/窗时更新。
- 最后再考虑 UI 自动化点击面板，不建议先做盲目的命令行关键字试错。
